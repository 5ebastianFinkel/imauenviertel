## Project Overview

This is a TanStack Start (React) website for "Im Auenviertel" Kleingartenverein (German allotment garden association). The site includes event management, blog posts, team profiles, and document downloads. It is fully prerendered at build time and deployed as static files.

## Commands

### Development
- `pnpm dev` - Start development server (http://localhost:4321)
- `pnpm build` - Build for production (prerenders all pages to `dist/client`, then writes the sitemap)
- `pnpm preview` - Preview production build

### Testing
- `pnpm test` - Run all tests
- `pnpm test:watch` - Run tests in watch mode
- `pnpm test:ui` - Run tests with Vitest UI

### Linting
- `pnpm lint` - Run oxlint on all source files
- `pnpm lint:fix` - Run oxlint with auto-fix for fixable issues
- `pnpm lint:ci` - Run oxlint for CI environments (fails on warnings)

### Type Checking
- `pnpm typecheck` - Generate the content collections, then run TypeScript type checking without emitting files
- `pnpm typecheck:watch` - Run TypeScript type checking in watch mode
- `pnpm typecheck:ci` - Same as `typecheck`, for CI environments
- `pnpm content` - Only regenerate the content collections (`.content-collections/`)

## Architecture

### Framework Stack
- **TanStack Start + TanStack Router** - React framework with file-based routing (`src/routes/`), configured in `vite.config.ts`
- **React 19** - Components in `src/components/`
- **Content Collections** - Typed Markdown content (`content-collections.ts`)
- **Tailwind CSS v4** - Utility-first CSS framework (using Vite plugin)
- **TypeScript** - Strict mode enabled
- **Vitest** - Unit testing framework

### Static Output
- `vite.config.ts` enables `prerender` with link crawling: every page is rendered to HTML in `dist/client`, which Netlify publishes. There is no server at runtime, so do not add server functions or server routes without also changing the hosting setup.
- Loaders import the generated collections directly (`import { allEvents } from "content-collections"`), which also bundles that data for client-side navigation.
- `src/server.ts` only exists so that `/404.html` can be prerendered from an unmatched URL; `src/components/NotFound.tsx` is the router's `notFoundComponent`.
- `scripts/sitemap.mjs` writes `sitemap.xml` from the canonical URLs of the prerendered pages.
- `src/routeTree.gen.ts` is generated by the router plugin; do not edit it by hand.

### Routing and Pages
- `src/routes/__root.tsx` - Document shell, site-wide head tags, header/footer layout
- `src/routes/*.tsx` - One file per page; each sets its title and canonical URL with `pageHead()` from `src/utils/seo.ts`
- Internal links use `<Link>` from `@tanstack/react-router`; downloads and external links are plain `<a>`
- Mind JSX whitespace: put `{" "}` before an inline element that starts a new line

### Styling
- `src/styles/globals.css` is the single stylesheet: design tokens, shared classes (`.btn`, `.eyebrow`, ...) and imports of `styles/components/*.css` and `styles/pages/*.css`
- Page styles are nested under a page class (`.home`, `.page-about`, ...) on the page's root element so they do not leak into other pages
- Scroll reveal: add `data-reveal` to an element and call `useScrollReveal()` (`src/utils/useScrollReveal.ts`) in that page component

### Content Management
Markdown files with frontmatter, validated by the zod schemas in `content-collections.ts`:
- `src/content/blog/` - Blog posts (Markdown, rendered to HTML at build time; MDX is not supported)
- `src/content/events/` - Event dates for garden activities
- `src/content/team/` - Team member profiles
- `src/content/documents/` - Downloadable documents
- `src/content/links/` - External links

Dates are stored as strings: events as `YYYY-MM-DD` (use `parseLocalDate` from `src/utils/content.ts`), publish dates as ISO timestamps.

### Images
- Images in `src/assets/` are resized by `vite-imagetools` through import queries, e.g. `import img from "@assets/photo.webp?w=480;800&format=webp&as=img"` (typed in `src/env.d.ts`)
- Blog images on Cloudinary (where Decap CMS uploads them) and Unsplash get a srcset of resized versions through URL parameters, see `src/utils/images.ts`. Only Cloudinary URLs of our cloud (`dc6swddrn`, as in `public/admin/config.yml`) are rewritten
- Other content images, such as the older files in `public/uploads/`, are used as they are; images in post bodies get `width`/`height` from the file at build time

### Decap CMS
- Admin panel lives in `public/admin/` (`config.yml`, `index.html`); the dev server maps `/admin` to it (see `adminDevRewrite` in `vite.config.ts`)
- The `decap-cms` script is pinned to an exact version with an SRI `integrity` hash; when upgrading, change version and hash in `public/admin/index.html` (see `DECAP_CMS_GUIDE.md` → "Updating Decap CMS")

### Key Features
- **ICS Calendar Generation** - `src/utils/icsGenerator.ts` creates downloadable calendar files
- **Event Management** - Calendar button component with download functionality
- **Document Downloads** - PDF files in `public/uploads/`
- **Multilingual Content** - German-language focused site

### Path Aliases
Configured in `tsconfig.json` (Vite and Vitest read them from there):
- `@components/*` → `src/components/*`
- `@utils/*` → `src/utils/*`
- `@assets/*` → `src/assets/*`
- `content-collections` → `.content-collections/generated` (generated, not committed)
